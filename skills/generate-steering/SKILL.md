# generate-steering

Generates a repo's basic steering docs, in standard Kiro format. It does not
create files or folders outside the repo's `.kiro/steering/`.

## When it activates

Automatically when a repo (or multi-root workspace) without steering docs is
detected, or when the user explicitly asks to regenerate them.

**Repo discovery** — same method as `find-connections`: do not rely on a
single top-level `list directory`. Use the workspace's multi-root
configuration if it exists, or recursively search for `.git` folders across
the whole tree if it does not — never assume all repos sit at a single
depth level.

## What it generates (automatic, always)

- `.kiro/steering/tech.md` — stack, language, main dependencies
- `.kiro/steering/structure.md` — folder organization, layers, repo patterns
- `.kiroignore` — standard exclusion patterns, including `.kiro/allspark/`
  (isolated environment and prescan results of `find-connections`:
  working artifacts that must not enter Kiro's context). If the
  `.kiroignore` already exists, only the missing lines are added, without
  deleting the team's lines.

See `references/steering-templates.md` for each file's template.

## What it does NOT generate automatically

- `database.md` — **excluded from the automatic flow.**
  - If one already exists from a previous run, it is respected as is, with
    whatever `inclusion` it has. It is not touched, deleted or regenerated.
  - It is only created if the current session prompt explicitly asks for it
    (e.g. "document the schema of this database").
- `moc.md` — **not this skill's responsibility.** The connection map is
  generated by the `find-connections` skill, separately, on demand.
  `generate-steering` never creates or touches it.

## Reset rules (new repo)

When a new repo is started and clean steering docs are requested, this skill
deletes and regenerates only what it generates itself: `tech.md`,
`structure.md`, `.kiroignore`.

- `database.md` is never deleted by this flow, whether it exists or not.
- `moc.md` is never deleted by this flow — its lifecycle is independent
  (see `find-connections`); it does not matter whether the repo was
  regenerated or not.

## Expected output

When done, it reports: which files it generated, which it left intact (and
why: "already existed", "database.md is not requested automatically"), and
whether it detected an existing `moc.md` to report that it remains valid.
